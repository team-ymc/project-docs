# Logging Conventions

- Status: Draft
- Source: ADR-006

## 1. 기본 규칙

- 한 이벤트는 JSON 한 줄로 남긴다.
- `message`는 사람이 읽는 설명, `event_action`은 조회와 집계를 위한 고정된 이름이다.
- 커스텀 필드는 소문자 `snake_case`를 사용한다.
- ID는 JSON 문자열로 기록하고 실제 형식은 해당 도메인 계약을 따른다.
- 같은 예외를 잡아서 다시 던지는 모든 지점에서 반복해 기록하지 않는다. 스택 트레이스는 원인을 처리하는 서비스 경계에서 한 번 남긴다.

## 2. 레벨

| 레벨 | 기준 | 예 |
|---|---|---|
| ERROR | 서버 실패로 요청이나 작업을 완료하지 못해 조사가 필요함 | 파싱 최종 실패, DB 저장 실패 |
| WARN | 이상이 있었지만 자동 복구했거나 곧 복구할 수 있음 | 재시도 후 성공, 폴백 동작 |
| INFO | 중요한 상태 변화 | 파싱 요청·완료, 채팅 실행 종료 |
| DEBUG | 로컬 개발에 필요한 세부 정보 | 민감정보를 제외한 재시도 횟수, 파서 단계 |

- prod의 기본 로그 레벨은 INFO 이상이다.
- 예상 가능한 사용자 입력 오류는 ERROR로 기록하지 않는다.
- 모든 ERROR를 즉시 알람으로 연결하지 않는다. 오류율, DLQ 깊이처럼 대응 기준이 있는 조건에 알람을 건다.

## 3. `event_action`

- 형식: `도메인.행위.결과`
- 예: `paper.parse.requested`, `paper.parse.completed`, `paper.parse.failed`, `chat.run.completed`
- `message` 문구는 바꿀 수 있지만 대시보드나 알람이 사용하는 `event_action`은 함부로 바꾸지 않는다.
- 여러 서비스가 공유하거나 대시보드·알람이 의존하는 값만 이 문서에 추가한다.

## 4. 스트림과 메시지

- SSE delta 또는 청크마다 로그를 남기지 않는다.
- 채팅 실행은 시작과 종료만 기록한다. 종료 로그에는 종료 상태와 소요시간을 포함한다.
- SQS 처리 로그에는 가능하면 메시지 ID와 수신 횟수를 포함해 재전달을 구분한다.

소요시간 필드는 서비스마다 단위가 달라지지 않도록 `duration_ms` 정수로 기록한다.

## 5. 남기지 않는 것

- 토큰·비밀번호·API 키 등 인증정보
- 논문 본문과 개인정보 원문
- 사용자 질문과 LLM 응답 본문
- HTTP·SQS payload 전체 덤프

본문 대신 도메인 ID, 길이, 토큰 수처럼 본문을 복원할 수 없는 값을 사용한다.

## 6. 구현 메모

- BE: Spring Boot ECS 구조화 로깅 + MDC
- AI: Python JSON formatter + contextvars
- 로컬 조회: `docker compose logs | jq`
