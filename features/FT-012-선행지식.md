# Feature: FT-012 선행지식

## 1. Overview

- Summary: 사용자는 논문 본문에 표시된 선행지식 용어를 눌러 해당 논문의 문맥에 맞는 영문·국문 설명을 확인할 수 있다.
- Status: In Progress
- Tracking: [Design v3 선행지식](../design/v3/README.md) · [ADR-011 선행지식 설명 캐시](../decisions/ADR-011-prerequisite-definition-redis-cache.md) · `contracts/frontend-backend/openapi.yaml` (`getPaperContent`, `createPrerequisiteDefinition`) · `contracts/backend-ai/openapi.yml` (`prerequisite-knowledge-agent-run`)
- Depends on: FT-003 논문 등록·분석, FT-004 논문 학습 뷰어

## 2. Feature Boundary

### In Scope

- 분석된 선행지식 용어를 논문 본문의 정확한 위치에 하이라이트
- 상단 토글로 선행지식 하이라이트를 표시하거나 숨김
- 하이라이트 선택 시 해당 논문 문맥에 맞는 영문·국문 설명을 팝오버로 제공
- 첫 조회에서 설명을 생성하고 같은 공유 Document의 같은 용어 설명을 재사용
- 설명 생성 중·성공·실패 상태와 30일 갱신 정책

### Out of Scope

- 사용자가 임의로 선택한 텍스트를 선행지식으로 등록 → 후속(post-MVP)
- 선행지식 설명 편집, 수동 새로고침과 생성 이력 조회 → 후속(post-MVP)
- 설명의 부분 스트리밍
- 최신 동향과 외부 사례를 검색하는 별도 retrieval → 후속(post-MVP)
- 선행지식 설명 생성의 사용자 사용량 차감

## 4. Stories

### Story 1. 사용자는 논문 본문에서 선행지식 용어를 구분할 수 있다 `MVP`

- type: USER
- Source: 학습 · 선행지식 설명
- Acceptance Criteria:
  - 분석 결과가 가리키는 정확한 본문 범위에만 선행지식 하이라이트가 표시된다.
  - 컴파일이 완료되기 전에는 본문 응답의 `prerequisiteHighlights` 빈 배열을 사용하며, 기존 `knowledgeGraphStatus` 폴링을 계속한다.
  - `knowledgeGraphStatus` READY가 되면 본문을 한 번 다시 조회해 컴파일된 하이라이트 배열을 받는다. 별도의 선행지식 준비 상태는 추가하지 않는다.
  - 하이라이트 배열이 있으면 토글을 활성화하고, 비어 있으면 비활성화한 뒤 `표시할 선행지식이 없습니다`를 툴팁으로 표시한다.
  - 토글은 처음에 꺼져 있다. 켜면 하이라이트를 표시하고, 끄면 받은 배열은 유지한 채 하이라이트와 열린 팝오버만 숨긴다.
  - 하이라이트 정보가 아직 준비되지 않았거나 유효하지 않아도 논문 본문 읽기는 막히지 않는다.
  - 같은 Document를 사용하는 사용자는 동일한 하이라이트 집합을 본다.
- Depends on: FT-003 Story 4, FT-004 Story 1

### Story 2. 사용자는 선행지식 설명을 같은 자리에서 열고 닫을 수 있다 `MVP`

- type: USER
- Source: 학습 · 선행지식 설명
- Acceptance Criteria:
  - 사용자가 하이라이트를 누르면 해당 범위 아래에 선행지식 설명 팝오버가 열린다.
  - 팝오버는 선택한 하이라이트 원문, 영문 정의, 구분선과 한국어 설명으로 구성하며 별도의 선행지식 태그·생성 근거 문구·닫기 버튼을 표시하지 않는다.
  - 팝오버와 선택한 하이라이트 바깥의 논문 뷰어 영역을 누르면 팝오버가 닫힌다.
  - 팝오버 내부, 목차 또는 AI 튜터 영역을 눌러도 팝오버가 닫히지 않는다.
  - 닫은 뒤 같은 하이라이트를 다시 누르면 설명을 다시 열 수 있다.
- Depends on: Story 1

### Story 3. 시스템은 선행지식 설명을 생성하고 같은 Document에서 재사용한다 `MVP`

- type: SYSTEM
- Source: 학습 · 선행지식 설명
- Acceptance Criteria:
  - 설명이 없는 용어를 처음 조회하면 해당 논문 문맥에 맞는 영문·국문 설명을 non-streaming으로 생성한다.
  - 같은 공유 Document 안에서 표기가 같은 용어는 등장 위치와 사용자에 관계없이 하나의 설명을 공유한다. 의미가 비슷하지만 표기가 다른 용어는 임의로 합치지 않는다.
  - 한 사용자는 선행지식 설명을 동시에 하나만 생성할 수 있다. 이미 생성 중이면 새 생성을 시작하지 않는다.
  - 서로 다른 사용자가 캐시에 없는 같은 설명을 동시에 요청해 중복 생성하는 것은 MVP에서 허용한다. 성공 결과 중 먼저 저장된 설명을 이후 요청이 재사용한다.
  - 성공한 설명은 생성 시점부터 30일 동안 재사용되며 조회만으로 갱신 기간이 연장되지 않는다.
  - 생성에 실패한 결과는 재사용하지 않으며 다음 조회에서 다시 생성할 수 있다.
  - 설명 생성 프롬프트·모델·출력 규칙이 바뀌면 generator version을 올려 이전 설명을 재사용하지 않는다.
  - 선행지식 설명 생성은 FT-011의 AI 질의 사용량을 차감하지 않는다. 실제 생성 비용은 운영 관측용으로만 기록한다.
- Depends on: Story 1

### Story 4. 사용자는 설명 생성 상태와 실패 여부를 확인할 수 있다 `MVP`

- type: USER
- Source: 학습 · 선행지식 설명
- Acceptance Criteria:
  - 처음 생성하는 동안에는 개념명이 있는 팝오버를 즉시 열고 설명 영역에 점 3개의 로딩 표시를 보여준다.
  - 생성이 완료되면 로딩 내용을 영문·국문 설명 전체로 한 번에 교체한다.
  - 생성에 실패하면 같은 팝오버에 `설명을 불러오지 못했습니다.`를 표시한다.
  - 별도 재시도 버튼은 제공하지 않는다. 사용자가 팝오버를 닫고 하이라이트를 다시 누르면 새 요청으로 재시도한다.
  - 재사용할 설명이 있으면 로딩 상태 없이 완성된 설명을 즉시 표시한다.
- Depends on: Story 2-3

## 5. Done Criteria

- 준비된 선행지식 범위가 본문에 정확히 하이라이트되고 팝오버의 열기·닫기 동작이 Design v3와 일치한다.
- 첫 설명 생성, 같은 Document 안의 결과 재사용, 30일 갱신과 실패 후 재시도가 검증된다.
- 선행지식 설명 생성은 사용자 AI 질의 사용량을 차감하지 않고 실제 생성 비용만 관측된다.

## 6. Open Questions

- 사용자당 동시 생성 1개를 보장하는 Redis 소유권 키의 만료·해제 세부 방식은 Backend 구현 설계에서 확정한다.
- 분당 요청 수와 IP 기반 운영 rate limit의 수치는 FT-011이 분리한 YMC-350에서 확정한다.
