# Feature: FT-011 플랜·사용량 제한

## 1. Overview

- Summary: 시스템은 사용자에게 Free 또는 Pro 플랜을 적용하고, 플랜에 따라 AI 답변과 문서 등록 가능 횟수를 제한하고 조회할 수 있게 한다.
- Status: In Progress
- Tracking: YMC-344 / `decisions/ADR-006-usage-reservation.md` / `contracts/frontend-backend/openapi.yaml` (`/api/me/plan`)
- Depends on: FT-001 소셜 인증, FT-003 논문 등록·분석, FT-007 AI 튜터 채팅

## 2. Feature Boundary

### In Scope

- 인증된 사용자의 유효 플랜을 Free 또는 Pro로 판정
- Free와 Pro 각각의 AI 질의·문서 등록 사용량 정책 적용
- 동시 요청이 한도를 초과하지 않도록 요청 단위 사용량 예약·확정·해제
- 현재 플랜, 만료 시각과 기능별 사용량·남은 횟수 조회

### Out of Scope

- 결제, 정기 구독, 자동 갱신, 환불과 PG 연동
- 이벤트 등으로 추가 횟수나 Pro 기간을 지급하는 리워드
- 현재 플랜·사용량을 상시 노출하는 UI의 진입 위치와 표현 방식 → YMC-348
- 토큰·모델 원가·크레딧을 기준으로 한 사용자 한도 판정 → 횟수로 시작
- 분당 요청 수, 동시 실행 수와 IP 기반 남용 방지 등 운영 rate limit → 별도 운영 정책

## 4. Stories

### Story 1. 시스템은 사용자의 유효 플랜을 판정한다 `MVP`

- type: SYSTEM
- Source Userflows: UF-002 Step 1-3, UF-003 Step 1-3
- Acceptance Criteria:
  - 모든 인증 사용자의 기본 플랜은 Free다.
  - 플랜에 영향을 받는 요청을 시작할 때 요청 시각을 기준으로 유효 플랜을 판정한다.
  - 요청 시각이 Pro 권한의 시작 시각 이상이고 만료 시각 미만이면 Pro를 적용한다.
  - 유효한 Pro 권한이 없으면 Free를 적용하며, 만료된 권한 기록을 변경하거나 삭제하지 않는다.
  - 롤링 베타의 Pro 권한은 사용자별 부여 시각부터 KST 달력상 1개월 후에 만료하며, 다음 달에 같은 일자가 없으면 말일의 같은 시각으로 보정한다. 계산된 시작·만료 시각은 UTC로 저장한다.
  - 요청 시작 시 판정한 플랜과 사용량 정책은 해당 실행이 종료될 때까지 유지한다.
  - Pro로 판정된 실행의 사용량은 Free 정책의 사용량을 소비하지 않는다.
- Depends on: FT-001

### Story 2. 시스템은 플랜·기능별 사용량을 제한한다 `MVP`

- type: SYSTEM
- Source Userflows: UF-002 Step 1-5, UF-003 Step 3-5
- Acceptance Criteria:
  - MVP 정책 모드는 KST 기준 `MONTHLY N`과 `UNLIMITED`만 지원한다.
  - 플랜과 기능의 조합마다 제한 횟수를 독립적으로 설정한다.
  - 제한 횟수는 코드에 고정하지 않고 배포 정책값으로 주입한다. 아래 표의 횟수는 베타 초기 정책값(YMC-349)이며, AC가 강제하는 것은 값이 아니라 확정 기준과 정책 구조다.

  | 사용량 구분 | 1회 사용 완료 확정 기준 | Free | Pro |
  |---|---|---|---|
  | AI 질의 | AI 완료 신호를 받은 뒤 기존 ASSISTANT row에 최종 답변이 저장되고 `GENERATING → COMPLETED` 전이가 commit됨 | 월 100회 | `UNLIMITED` |
  | 문서 등록·파싱 | 해당 사용자의 `Paper`가 신규 파싱 또는 기존 결과 재사용을 통해 `COMPLETED`로 commit됨 | 월 3회 | `UNLIMITED` |

  - 현재 플랜·기능 정책이 유한한 경우 외부 처리를 시작하기 전에 사용 가능 횟수 1회를 예약한다.
  - 성공 완료 기준을 충족하면 예약한 1회를 사용 완료로 확정한다.
  - AI 실행 실패, timeout, protocol 오류, 최종 답변 저장 실패, 문서 업로드 만료 또는 문서 처리의 최종 `FAILED`에서는 예약을 해제한다.
  - 같은 요청이나 terminal 결과가 재전달돼도 같은 실행은 한 번만 예약·확정한다.
  - 남은 횟수가 없으면 AI 실행이나 문서 등록을 시작하지 않고 기능별 사용량 한도 초과를 반환한다.
  - 기존 파싱 결과를 재사용해도 사용자에게 학습 가능한 `Paper` 한 건이 등록됐으므로 문서 사용량 1회로 확정한다.
  - 답변 생성 중 채팅 세션을 논리 삭제해도 AI 실행과 예약을 취소하지 않고, terminal 결과에 따라 사용량을 정산하며 세션 데이터는 논리 삭제 상태로 보관한다.
  - 완료된 대화·메시지·문서를 삭제해도 이미 확정된 사용 완료 횟수는 복구하지 않는다.
  - `UNLIMITED` 정책도 성공 완료 횟수를 운영 관측을 위해 기록한다.
- Depends on: Story 1, FT-003 Story 1-5·7, FT-007 Story 2

### Story 3. 시스템은 현재 플랜과 남은 횟수 조회를 제공한다 `MVP`

- type: SYSTEM
- Source Userflows: UF-002 Step 1-3, UF-003 Step 1-3
- Acceptance Criteria:
  - 인증 사용자는 현재 유효 플랜과 Pro 권한 만료 시각을 조회할 수 있다.
  - 현재 플랜에 유한한 정책이 적용된 사용자는 AI 질의와 문서 등록 각각의 적용 기간, 상한, 현재 사용량과 현재 요청 가능한 남은 횟수를 조회할 수 있다.
  - 현재 사용량은 확정된 사용량과 진행 중인 예약을 합산하며, 예약이 해제되면 감소한다.
  - `MONTHLY`는 다음 월간 버킷이 시작되는 시각을 제공하며, `UNLIMITED`는 초기화 시각을 제공하지 않는다.
  - 현재 플랜·기능 정책이 `UNLIMITED`이면 운영 관측용 성공 횟수는 노출하지 않고 `UNLIMITED`로 표시할 수 있는 값만 반환한다.
  - 한도에 도달한 상태에서 요청하면 기능별로 구분 가능한 안정된 오류 코드를 반환한다.
- Depends on: Story 1-2

## 5. Done Criteria

- 기본 Free 사용자와 유효한 Pro 사용자의 플랜 판정이 만료 시각을 포함해 동작한다.
- Free와 Pro의 기능별 정책값이 독립적으로 적용되고, 유한한 한도는 동시 요청과 중복 완료에서도 초과·중복 차감되지 않는다.
- 성공 완료는 사용량으로 확정되고 실패·만료된 요청의 예약은 해제된다.
- 현재 플랜과 기능별 사용량을 조회할 수 있고, FE가 기능별 한도 초과를 구분해 안내할 수 있다.

>

>
> **Resolved** — 베타 초기 정책은 Free AI 질의 월 100회, 문서 등록 월 3회, Pro는 두 기능 모두 `UNLIMITED`다. 유한 정책의 월간 버킷은 KST 매월 1일 00:00에 시작하며, 설정 반영은 YMC-349에서 추적한다.
>
> **Resolved** — 롤링 베타 Pro는 공통 만료일을 두지 않고 사용자별 부여 시각부터 KST 달력상 1개월을 제공한다. 월말 일자는 다음 달의 말일로 보정하고 계산된 만료 시각을 UTC로 저장한다.
>
> **Resolved** — AI 모델 호출별 모델명과 토큰 사용량은 AI 서버 내부에서 집계한다. AI 서버는 성공 완료된 질의의 추정 비용만 BE에 전달하고, BE는 이를 횟수 한도 판정과 분리된 관측 데이터로 저장한다. 실패·timeout된 질의의 비용은 BE에 저장하지 않는다.
>
> **Resolved** — MVP는 같은 채팅 세션의 AI 실행을 1개로 제한하되, 서로 다른 세션의 질의를 막는 사용자 전체 동시 실행 제한은 두지 않는다.
>
> **Resolved** — 운영 rate limit은 플랜별 월간 횟수 제한과 분리하며 FT-011 범위에 포함하지 않는다. AI 질의 경로의 부하 테스트 후 수치와 Serverless Valkey 도입 여부를 YMC-350에서 결정한다.
