# Feature: FT-011 플랜·사용량 제한

## 1. Overview

- Summary: 시스템은 사용자에게 Free 또는 Pro 플랜을 적용하고, 플랜에 따라 AI 답변과 문서 등록 가능 횟수를 제한하고 조회할 수 있게 한다.
- Status: In Progress
- Tracking: YMC-344
- Depends on: FT-001 소셜 인증, FT-003 논문 등록·분석, FT-007 AI 튜터 채팅

## 2. Feature Boundary

### In Scope

- 인증된 사용자의 유효 플랜을 Free 또는 Pro로 판정
- Free와 Pro 각각의 AI 질의·문서 등록 사용량 정책 적용
- 동시 요청이 한도를 초과하지 않도록 요청 단위 사용량 예약·확정·해제
- 현재 플랜, 만료 시각과 기능별 사용량·남은 횟수 조회

### Out of Scope

- 결제, 정기 구독, 자동 갱신, 환불과 PG 연동
- 이벤트 등으로 추가 횟수나 Pro 기간을 지급하는 리워드
- 토큰·모델 원가·크레딧을 기준으로 한 사용자 한도 판정 → 횟수로 시작
- 분당 요청 수, 동시 실행 수와 IP 기반 남용 방지 등 운영 rate limit → 별도 운영 정책

## 4. Stories

### Story 1. 시스템은 사용자의 유효 플랜을 판정한다 `MVP`

- type: SYSTEM
- Source Userflows: UF-002 Step 1-3, UF-003 Step 1-3
- Acceptance Criteria:
  - 모든 인증 사용자의 기본 플랜은 Free다.
  - 플랜에 영향을 받는 요청을 시작할 때 요청 시각을 기준으로 유효 플랜을 판정한다.
  - 요청 시각이 Pro 권한의 시작 시각 이상이고 만료 시각 미만이면 Pro를 적용한다.
  - 유효한 Pro 권한이 없으면 Free를 적용하며, 만료된 권한 기록을 변경하거나 삭제하지 않는다.
  - 요청 시작 시 판정한 플랜과 사용량 정책은 해당 실행이 종료될 때까지 유지한다.
  - Pro로 판정된 실행의 사용량은 Free 정책의 사용량을 소비하지 않는다.
- Depends on: FT-001

### Story 2. 시스템은 플랜·기능별 사용량을 제한한다 `MVP`

- type: SYSTEM
- Source Userflows: UF-002 Step 1-5, UF-003 Step 3-5
- Acceptance Criteria:
  - 플랜과 기능의 조합마다 제한 횟수와 적용 기간을 독립적으로 설정할 수 있다.
  - 초기 Pro 정책은 `UNLIMITED`를 사용할 수 있지만, 이후 사용 데이터에 따라 코드 흐름을 바꾸지 않고 유한한 N회 정책으로 전환할 수 있다.
  - 제한 횟수는 FT-011에 숫자로 고정하지 않고 배포 전에 정책값으로 확정한다.

  | 사용량 구분 | 1회 사용 완료 확정 기준 | Free | Pro |
  |---|---|---|---|
  | AI 질의 | AI 완료 신호를 받은 뒤 기존 ASSISTANT row에 최종 답변이 저장되고 `GENERATING → COMPLETED` 전이가 commit됨 | 정책에서 정한 기간당 N회 | 정책에서 정한 기간당 N회 또는 `UNLIMITED` |
  | 문서 등록·파싱 | 해당 사용자의 `Paper`가 신규 파싱 또는 기존 결과 재사용을 통해 `COMPLETED`로 commit됨 | 정책에서 정한 기간당 N회 | 정책에서 정한 기간당 N회 또는 `UNLIMITED` |

  - 현재 플랜·기능 정책이 유한한 경우 외부 처리를 시작하기 전에 사용 가능 횟수 1회를 예약한다.
  - 성공 완료 기준을 충족하면 예약한 1회를 사용 완료로 확정한다.
  - AI 실행 실패, timeout, protocol 오류, 최종 답변 저장 실패, 문서 업로드 만료 또는 문서 처리의 최종 `FAILED`에서는 예약을 해제한다.
  - 같은 요청이나 terminal 결과가 재전달돼도 같은 실행은 한 번만 예약·확정한다.
  - 남은 횟수가 없으면 AI 실행이나 문서 등록을 시작하지 않고 기능별 사용량 한도 초과를 반환한다.
  - 기존 파싱 결과를 재사용해도 사용자에게 학습 가능한 `Paper` 한 건이 등록됐으므로 문서 사용량 1회로 확정한다.
  - 완료된 대화·메시지·문서를 삭제해도 이미 확정된 사용 완료 횟수는 복구하지 않는다.
  - `UNLIMITED` 정책도 성공 완료 횟수를 운영 관측을 위해 기록한다.
- Depends on: Story 1, FT-003 Story 1-5, FT-007 Story 2

### Story 3. 사용자는 현재 플랜과 남은 횟수를 확인할 수 있다 `MVP`

- type: USER
- Source Userflows: UF-002 Step 1-3, UF-003 Step 1-3
- Acceptance Criteria:
  - 인증 사용자는 현재 유효 플랜과 Pro 권한 만료 시각을 조회할 수 있다.
  - 현재 플랜에 유한한 정책이 적용된 사용자는 AI 질의와 문서 등록 각각의 적용 기간, 상한, 사용 완료 횟수와 현재 요청 가능한 남은 횟수를 조회할 수 있다.
  - 진행 중인 예약은 사용 완료 횟수에는 포함하지 않지만 현재 요청 가능한 남은 횟수에는 반영한다.
  - 기간별 정책은 다음 사용량 기간이 시작되는 시각을 제공하며, `LIFETIME`과 `UNLIMITED`는 초기화 시각을 제공하지 않는다.
  - 현재 플랜·기능 정책이 `UNLIMITED`이면 상한과 남은 횟수 대신 `UNLIMITED`로 표시할 수 있는 값을 반환한다.
  - 한도에 도달한 상태에서 요청하면 기능별로 구분 가능한 안정된 오류 코드를 반환한다.
- Depends on: Story 1-2

## 5. Done Criteria

- 기본 Free 사용자와 유효한 Pro 사용자의 플랜 판정이 만료 시각을 포함해 동작한다.
- Free와 Pro의 기능별 정책값이 독립적으로 적용되고, 유한한 한도는 동시 요청과 중복 완료에서도 초과·중복 차감되지 않는다.
- 성공 완료는 사용량으로 확정되고 실패·만료된 요청의 예약은 해제된다.
- FE가 현재 플랜과 기능별 사용량을 조회하고 한도 초과를 구분해 안내할 수 있다.

## 6. Open Questions

- 현재 플랜과 남은 횟수를 어느 화면에 항상 노출할지, 한도 도달 전 사전 안내를 어떤 Wireframe으로 제공할지 결정 필요
- Free·Pro의 AI 질의와 문서 등록 각각에 적용할 N과 기간(`DAILY`, `WEEKLY`, `MONTHLY`)을 배포 전에 확정
- 기간별 사용량이 갱신되는 기준 timezone과 경계(일간 갱신 시각, 주간 시작 요일, 월간 시작일)를 배포 전에 확정
- 베타 Pro의 실제 만료 일시와 기준 timezone을 운영 시작 전에 확정해야 한다.
- 모델명과 input/output token을 한도 판정과 분리된 비용 관측 데이터로 MVP부터 수집할지 결정해야 한다.
- 운영 rate limit과 사용자별 동시 AI 실행 수의 구체적인 값은 부하 테스트 후 결정한다.

> **Resolved** — MVP 플랜은 Free와 Pro만 둔다. 두 플랜 모두 기능별 사용량 정책을 가질 수 있으며, 초기 Pro는 `UNLIMITED`로 시작한 뒤 사용 데이터에 따라 유한한 N회 정책으로 변경할 수 있다.
>
> **Resolved** — AI 질의는 ASSISTANT row의 최종 답변 저장과 `COMPLETED` 전이 commit, 문서는 사용자 `Paper`의 `COMPLETED` 전이 commit을 1회 사용 완료 기준으로 삼는다. 유한한 정책에서는 동시 요청의 한도 우회를 막기 위해 실행 전에 1회를 예약하고, 성공 시 확정하며 실패·만료 시 해제한다. 같은 실행과 중복 완료 신호는 한 번만 반영한다.
>
> **Resolved** — 베타 테스터의 Pro 부여는 초기 운영 DML이며 사용자 제품 역량이 아니므로 별도 Feature Story로 두지 않는다. 결제·자동 갱신은 MVP에 포함하지 않는다.
